# 人才培养

## 用户版成果输出

专业交付统一规则：一级标题必须使用固定编号并去掉“技能”后缀；二级标题使用“1.1”式固定编号；三级标题依次使用“核心判断、深度分析、依据与边界、落地建议”并使用“1.1.1”式固定编号；四级标题继续拆分为“关键变量、推导逻辑、已知事实、待验证信息、执行动作、验收指标、风险与停止条件”并使用“1.1.1.1”式固定编号。每个业务分析子项至少500个有效字符，必须形成该岗位专属的专业推导，事实、推断与信息缺口分开，必要说明使用括号标注；禁止统一模板扩写、重复套话或用篇幅冒充分析深度。

唯一目录事实源为 `control-center/registries/organization-output-standard.json`。本技能在用户版组织 Word 中固定使用一级章节“人才培养”，并严格按以下顺序输出：

1. 新人培养
2. 岗位训练
3. 员工成长路径
4. 企业知识传承

每个栏目必须绑定已确认岗位标准、真实业务场景和培养对象资料；不能把所有业绩问题归因于培训。仍缺少企业内部不可替代事实时写明：`信息不足，暂时无法形成可靠分析。当前缺少：<具体信息>。` 能力模型、评估认证、导师反馈和复训条件融入对应栏目，不新增用户版目录。

## 概览

把同企业已批准人才配置资产中的岗位职责与人才标准，转成可执行的能力模型、培养体系、课程训练、真实工作任务、评估认证、复训机制和成长路径。培养结果只为使用者提供决策依据，不自动执行任何人员决定。

## 适用场景

- 新人培养、岗位训练、管理者培养和在岗能力提升；
- 培训体系、课程模块、实战任务、导师反馈和知识传承；
- 能力评估、上岗认证、复训安排和专业/管理成长路径。

不用于重新定义岗位，不把所有业绩问题归因于培训，也不自动处理转正、晋升、调岗、调薪、奖惩或辞退。

## 输入

企业编号、任务编号、使用者原话、权限包、同企业已批准人才配置资产的精确版本与 SHA-256、岗位职责、人才画像、真实业务场景、已有课程资料、培养对象资料（如已授权）、目标成果和限制条件。

## 固定步骤

1. 读取根级与组织规则，绑定唯一企业、任务、培养对象和权限，执行企业隔离。
2. 按 `organizations/ai-organization-officer/workflows/TALENT_DEVELOPMENT_PILOT.md` 执行飞书知识前置；保存 `matched`、`no_hit` 或 `degraded` 凭证，无命中或降级不得虚构依据。
3. 固定读取已批准人才配置资产的 `capabilityId@version` 与 SHA-256；岗位标准变化时停止旧培养版本，不静默继承。
4. 诊断差距来源，分别检查能力、管理、流程、资源、工具、激励、岗位匹配和业务变化；只有证据支持时才进入培训方案。
5. 建立岗位能力模型，明确每项能力的目标等级、可观察行为和所需证据。
6. 设计培养目标、课程模块、标准示范、练习、场景模拟、真实工作任务、常见错误、导师支持和反馈节奏。通用入职资料不能代替岗位训练。
7. 设计评估与认证，必须结合至少两类证据，并包含真实工作任务；单次考试不得形成永久标签。
8. 设计成长路径、替代发展路径、认证失效条件、复训条件和培养运营指标。
9. 执行企业、权限、知识、上游资产、证据、隐私、公平、版本和人员决定门禁，形成流程复制下游简报。
10. 提交使用者最终决定。AI不得自动决定转正、晋升、降职、调岗、调薪、奖惩、绩效定级或辞退，也不得未经授权发布培训或认证结果。
11. 批准后保存使用者原话、范围、时间与候选 SHA-256；正式版本不覆盖，生成企业正式培养资产、当前版本指针和 `return-package.json`。
12. 真实执行后复盘课程有效性、工作迁移效果、错误复发和岗位变化；需要修改时创建新版本。

## 输出

培养需求诊断、岗位能力模型、培养目标、课程与训练体系、真实工作任务、导师与反馈计划、评估认证规则、成长路径、复训条件、运营指标、风险未知、流程复制下游简报、候选版本、批准记录、正式资产和回传包。

## 依赖

飞书知识前置服务、人才配置正式资产、组织任务状态机、人才培养候选契约与门禁、企业隔离存储、通用正式晋级组件和控制中心协作契约。

## 质量检查

- 企业、任务、权限、培养对象、知识凭证和候选版本一致；
- 精确绑定已批准人才配置资产及其 SHA-256；
- 培养需求已排除管理、流程、资源等主要非能力原因；
- 每个模块都有示范、练习、真实或高保真实战、错误案例和评分标准；
- 评估使用至少两类证据，单次考试不永久定性；
- 认证与人员处理分离，所有高影响人员事项由使用者最终决定；
- 正式资产、批准原话、候选哈希、当前指针和回传包一致；
- 已形成可供流程复制使用的 SOP、表单、知识和版本需求。

## 异常处理

跨企业、越权、上游岗位资产漂移、候选哈希不一致、伪造人员表现、歧视性标准、自动人员决定或覆盖旧正式版本时立即停止。课程与考核不一致、工具资源不齐或评分争议时，相关成绩无效并进入复核。

## 重试条件

仅对临时知识服务、文件并发、可修正字段和一次评分校准进行有限重试。每次记录根因、修正和证据；同一根因最多三轮。

## 停止条件

同一根因三轮仍失败、缺少不可替代岗位事实、无法取得必要权限、要求自动人员决定、要求未经批准外部发布、岗位标准已变更或组织自检失败时，停止对应动作并报告。补训与重考不得无限循环。

## 示例

“三天培训，80分以下直接淘汰”不能直接执行。先固定岗位任务和合格样例，区分培训、管理、流程与资源原因；80分可作为初步上岗认证线，低于标准进入复核、补训、等难度重考或岗位匹配评估。最终转正、调岗或辞退仍由使用者基于完整证据决定。

## V2总控调用与自动规划

总控传入企业、项目、任务、主责Skill、目标、授权链、权限、固定输入和使用者决定边界。本Skill支持单Skill、连续链和继续执行，不静默修改上游岗位标准。

## V2完整生产链

已批准岗位与人才标准 → 判断是否真是培训问题 → 能力差距 → 培养目标 → 六级学习路径 → 课程与岗位训练 → 真实工作任务 → 导师反馈 → 评估与认证 → 成长路径 → 知识传承 → 效果复盘 → 流程复制交接 → 总控回传。

### 判断是否真是培训问题

区分不知道、不会做、会做但未执行、流程工具、目标标准、管理反馈、激励、人岗和资源问题。不是能力问题时，不得用重复培训掩盖其他根因。

### 能力差距与六级路径

用真实证据比较当前与目标等级：理解 → 在指导下完成 → 独立完成 → 处理异常 → 教会他人 → 优化并复制。每级具备任务、质量、证据和晋级条件。

### 实战、导师、评估与认证

每个模块包含示范、正反例、练习、模拟、真实工作任务、错误、评分和导师职责。导师反馈指向具体行为和成果。认证至少两类证据，限定岗位、能力、等级、范围和版本；评分未校准时成绩无效。

### 成长路径、知识传承与效果复盘

支持专业、管理和跨岗位成长路径。知识只有在他人可复现并验证后才进入正式候选。复盘学习、能力、行为、业务结果、成本和复训率；补训不得无限循环。

## V2调试与恢复

全员失败优先检查课程、标准、工具和流程；会考试不会工作增加真实任务；课程脱岗退回岗位成果；评分不一致重新校准；补训无效判断人岗、管理或流程；岗位标准变化暂停旧版并形成上游变更请求；材料过期建立新版本。

同一根因最多三轮。恢复固定原企业、项目、任务、岗位版本、计划版本和安全检查点，不重放未确认的非幂等动作。

## V2交接与总控回传

向流程复制交接培养路径、课程、真实任务、导师、评估与认证、成长路径、知识传承、常见错误和精确版本。总控回传携带状态、成果、证据、质量、决定、风险、限制和恢复点；全部高影响人员事项仍由使用者最终决定。
