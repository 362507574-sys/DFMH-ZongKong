# 人才培养正式执行Workflow

## 定位

本Workflow把已经批准的岗位标准转成能力模型、课程、训练、实战、评估、认证和成长路径候选。文件名保留`PILOT`作为首轮实践兼容路径；自2026-07-29完成真实候选、使用者批准、异常验证和链路回归后，它是人才培养正式Skill 1.0.0的执行基线。根级是否正式接单仍由控制中心注册状态决定。

## 固定步骤

### 1. 绑定企业、岗位、培养对象和权限

- 读取唯一企业、人才培养任务和已批准人才配置正式资产。
- 培养对象可以是新人、在岗员工、管理者或数字岗位；没有真实人员资料时不得虚构个人表现。
- 跨企业、过期权限或上游岗位哈希不一致立即停止。

### 2. 飞书知识前置

- 查询岗位培养、训练、实战、认证、成长路径和相关业务知识。
- 保存`matched`、`no_hit`或`degraded`凭证；无命中或降级继续，但不得伪造内部依据。
- 临时失败最多两次重试。

### 3. 判断问题是否真的需要培养

分别检查能力、岗位要求、管理反馈、流程、工具资源、绩效口径、意愿和业务变化。不能把所有经营问题都归结为员工不会。

### 4. 建立岗位能力模型和培养目标

每项能力必须对应已批准岗位职责、可观察行为、目标等级和证据。培养不能静默修改岗位标准。

### 5. 设计课程、训练和实战

每个模块包含目标、材料、标准示范、练习、场景模拟或真实工作任务、常见错误和评分标准。通用入职材料不能替代岗位训练。

### 6. 配置导师、反馈和成长路径

明确导师角色、反馈周期、资源、阶段节点、目标等级、专业或管理替代路径。

### 7. 设计评估、认证和复训

至少结合两类证据，例如工作成果、实操、项目表现、主管反馈或复盘。单次考试不得永久定性；认证结果只供使用者最终决定。

### 8. 质量门禁

检查企业与岗位一致性、知识凭证、事实与未知、隐私、公平、可执行性、版本、上游影响和流程复制下游简报。

### 9. 使用者决策

- `approve`：保存原话、范围、时间和候选SHA-256，进入小范围试运行。
- `revise`：创建新版本，不覆盖旧版。
- `reject`：保留候选和原因。

AI不得自动决定转正、晋升、降职、调岗、调薪、奖惩、绩效定级或辞退；未经授权不得外部发布培训或认证结果。

### 10. 试运行、修订与正式晋级

使用真实岗位任务验证训练可执行性，记录事实反馈并创建新版本。只有重新通过全部门禁并取得使用者批准后，才能写入当前企业正式培养资产和结果包。

### 11. 复盘

记录自动继承资料、必须补充事实、知识命中质量、错误案例、真实修改、认证有效性、复训条件和需要流程复制沉淀的内容。

## 重试与停止

- 临时知识服务、文件占用和可修正字段错误可以有限重试。
- 同一根因最多三轮；第三轮仍失败时停止、保留证据并报告。
- 跨企业、越权、伪造人员表现、自动人员决定、未授权外部写入、不可逆覆盖或根级兼容失败时立即停止。

## 非技术交付顺序

培养诊断 → 岗位能力模型 → 培养目标 → 课程与训练 → 实战任务 → 评估认证 → 成长路径 → 风险未知 → 流程复制简报 → 使用者待决策事项。

## V2全闭环

总控调用 → 判断是否真是培训问题 → 能力差距 → 六级路径 → 课程与真实工作任务 → 导师反馈 → 至少两类证据评估与认证 → 成长路径 → 知识传承 → 效果复盘 → 流程复制交接 → 总控回传。

全员失败先检查系统性根因；补训不得无限循环。岗位标准漂移时暂停旧版本并提交上游变更请求，恢复时固定原企业、项目、任务和安全检查点。
