# 淘宝电商套图卖点提炼模板

## 使用门禁

本模板只用于卖点提炼。不要直接生图，不要复杂分析。任务范围未确认、素材与事实未归档时停止；最终卖点未经用户确认时，禁止进入淘宝首图组（首页图）或详情页提示词规划。

## 输入

- 产品名称：`{{product_name}}`
- 产品类目、定位与目标买家：`{{category_positioning_and_buyer}}`
- 主要使用场景与买家最在意的问题：`{{use_scenarios_and_buyer_pains}}`
- 产品图片与可见事实：`{{image_visible_facts}}`
- 用户明确提供的事实：`{{user_confirmed_facts}}`
- 正式产品资料及定位：`{{document_proven_facts}}`
- 目标范围：`{{scope_mode}}`

## 提炼要求

1. 先判断该类产品的购买决策逻辑，再整理卖点；图片可见不等于购买价值更高，禁止从外观细节开始凑数。
2. 只使用图片可见事实、用户明确说明或正式资料可以证明的信息，禁止编造。`sellingPoints.items.evidenceType` 仅允许 image_visible、user_confirmed、document_proven。
3. 每个候选卖点必须先归入一种购买角色：
   - `core_purchase_driver`：直接影响购买决定的核心效果、功能、使用结果或主要痛点；
   - `supporting_benefit`：支撑核心效果的材质、结构、机制、舒适性、便利性或适用场景；
   - `appearance_differentiator`：配色、造型、纹理、装饰或其他外观差异。
4. 排序固定为：买家痛点与使用结果 → 核心功能或性能 → 支撑机制、材质与场景 → 外观差异。只要有已验证的 `core_purchase_driver`，正式清单就必须优先保留，不能因为图片里看不见而被外观项替代。
5. 用户明确提供的轻量、透气、缓震、防滑等产品事实属于 `user_confirmed`，可以进入正式卖点；但不得自行添加数值、等级、检测结论、材质成分或认证。
6. 相近卖点允许合并，但合并后必须完整保留原始含义。例如“轻量+久走不累”“缓震+高回弹”“防滑+耐磨”可以形成一个更强主题，禁止直接遗漏其中任一已确认核心利益。
7. 非外观主导类目中，外观项通常最多保留 1–2 个；配色、鞋带、纹理、局部轮廓等相近细节必须合并，禁止拆成多条占满 5–8 个名额。只有首饰、服饰、家居装饰等明确以审美为主要购买理由的类目，记录 `appearance_led_exception=true` 后，才允许提高外观项占比。
8. 每项必须写清 `purchaseRole`、`buyerBenefit`、`visualProof` 和 `claimBoundary`：
   - `buyerBenefit`：买家为什么会因此更愿意购买；
   - `visualProof`：后续图片中能诚实展示的结构、材质、动作、场景或对比；不能把视觉效果冒充实验数据；
   - `claimBoundary`：不得越过的表述边界。主观绝对话术应改成有边界的表达，如“久走不累”可写成“久走更轻松”，除非有正式资料证明绝对结论。
9. 每个卖点使用唯一编号 `S01`、`S02`……并给出适合上图的短标题、简洁文案、可追踪证据来源和适用位置。
10. 以 5-8个适合淘宝展示的卖点为目标，不把数量当硬性上限。已验证核心卖点超过 8 个时，优先语义合并并标出覆盖关系；无法合理合并时全部保留并请用户定优先级，禁止用外观项替换核心项。
11. 正式卖点表只输出已验证项。参考图、竞品图和行业案例只能用于视觉启发，不得作为本产品事实证据。
12. 如果只有图片，且该类产品最重要的功能、性能或使用结果没有证据，即使可见外观事实达到 5 项，也只输出“已确认可见事实 + 待确认核心卖点”，暂停最终确认和提示词生成，不得把外观拼成伪完整卖点表。
13. 证据不足的内容写入独立的证据缺口清单；unsupported 只允许作为独立证据缺口状态或描述，禁止作为 `sellingPoints.items` 的 `evidenceType`，禁止用 unsupported 项凑数。
14. 已验证且具有购买价值的卖点少于 5 项时，暂停最终确认和提示词生成；只有记录用户明确批准少于5项的例外，才可继续。
15. 完成首图组/详情页分配，确保首页负责抓住核心购买驱动，详情页负责展开证明、支撑与场景。

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| S01 | `core_purchase_driver` |  |  |  |  |  |  |  |  | 是 |

最后单独输出：

- 核心购买驱动覆盖检查：`{{core_driver_coverage}}`
- 外观项数量及是否启用外观主导例外：`{{appearance_count_and_exception}}`
- 证据缺口及待补资料：`{{evidence_gaps}}`
- 首页候选卖点编号：`{{home_claim_ids}}`
- 详情页候选卖点编号：`{{detail_claim_ids}}`
- 最终确认门禁：当前仅为卖点草案；达到 5 项下限后，必须由用户明确确认最终完整卖点清单并记录确认原话与时间，才能规划提示词。少于 5 项时必须先补证据，或记录用户对例外数量的明确批准。
